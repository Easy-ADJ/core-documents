## 🔗 통합 테스트

서비스 3개를 병렬로 개발하므로 **각자 완성해도 합쳐지지 않으면 데모가 불가능하다.** 그래서 두 번 나눠 붙여본다.

| | 08.17 (스모크) | 08.21 (전체) |
|---|---|---|
| 목적 | 연결만 확인 — 주소·인증·타임아웃 | 시나리오 검증 — 금액이 끝까지 맞는지 |
| 범위 | 각 API를 한 번씩 호출해 200이 오는지 | 결제 → 원장 분개 → 정산 배치 → 대사 → 지급 |
| 기준 | 세 서버가 Railway에 떠 있고 서로 부를 수 있다 | 기사 1명의 결제 3건이 정산 1건으로 맞아떨어진다 |

- 팀밋업(08.18) 전에 치명적 불일치를 걸러내려고 1차를 앞에 뒀다. 계약이 어긋났다면 여기서 드러난다.
- 2차까지 4일 여유가 있어 1차에서 나온 문제를 고칠 시간이 남는다.
- **원장 API를 가장 먼저 고정해야 한다.** 정산이 원장 API 3개에 의존하므로 원장이 늦으면 정산이 통째로 막힌다.
  특히 `GET /api/ledger/unpaid?date=`와 `GET /api/ledger?driver_id=` 응답 스키마가 1차 전에 나와야 한다.

> ⚠️ Railway는 유휴 시 인스턴스가 잠들 수 있다. 테스트·발표 직전에 세 서버를 한 번씩 깨워둔다.
